# UNet++ PyTorch：环境、数据、训练与推理

来源是 [MrGiovanni/UNetPlusPlus 的 pytorch 目录](https://github.com/MrGiovanni/UNetPlusPlus/tree/master/pytorch)（官方说明里的 `master` 快照）。这套代码建立在 nnU-Net 1.6.4 上，包名仍是 `nnunet`。

官方仓库已经带有训练和推理，不需要另写脚本：

| 作用 | 命令 | 代码 |
| --- | --- | --- |
| 把 MSD 的 4D NIfTI 拆成 nnU-Net 格式 | `nnUNet_convert_decathlon_task` | `nnunet/experiment_planning/nnUNet_convert_decathlon_task.py` |
| 实验规划与预处理 | `nnUNet_plan_and_preprocess` | `nnunet/experiment_planning/nnUNet_plan_and_preprocess.py` |
| 训练 | `nnUNet_train` | `nnunet/run/run_training.py` |
| 推理 | `nnUNet_predict` | `nnunet/inference/predict_simple.py` |
| 根据交叉验证决定连通域后处理 | `nnUNet_determine_postprocessing` | `nnunet/postprocessing/consolidate_postprocessing_simple.py` |

UNet++ 的训练器是 `nnUNetPlusPlusTrainerV2`，网络是 `Generic_UNetPlusPlus`。官方 README 里的肝脏实验命令就是用这个训练器。

## 1. 用 uv 复现环境

在 `UNetPlusPlus/pytorch` 目录执行。Python 固定为 3.10（`.python-version`），依赖写在 `pyproject.toml`，精确版本在 `uv.lock`。另一台电脑只需要安装 [uv](https://docs.astral.sh/uv/)，然后：

```bash
cd UNetPlusPlus/pytorch
uv python pin 3.10
uv sync
```

`uv sync` 会按锁文件创建 `.venv` 并安装可编辑的 `nnunet`。之后用 `uv run <命令>`，不必手动 `activate`。

已核对可以导入的入口：`GenericPreprocessor`、`nnUNetPlusPlusTrainerV2`、`nnUNet_train`、`nnUNet_predict`、`nnUNet_plan_and_preprocess`。

版本约束里有两处是为了和这份旧代码对齐，不要随便放宽：

- `batchgenerators==0.21`。0.25 及以后的包不再从 `batchgenerators.dataloading` 导出 `MultiThreadedAugmenter`，训练数据增强会导入失败。
- `scipy>=1.9,<1.15`。预处理和滑窗推理还在使用 `scipy.ndimage.interpolation` 与 `scipy.ndimage.filters`，这两个子模块在 SciPy 1.15 中被删除。

当前锁文件里的 PyTorch 是 `2.14.1`。Linux 轮子带 CUDA 依赖；本机 Windows 装到的是 CPU 轮子（`2.14.1+cpu`）。有 NVIDIA GPU 的 Windows 机器如果要训练，需要改用 PyTorch 官方 CUDA 索引重新锁定，不能假设这份 Windows 环境自带 GPU 版 PyTorch。

## 2. 三个路径环境变量

`nnunet/paths.py` 在导入时读取它们。没设置时，规划、训练、推理都会直接退出。请在**同一终端**里先设置，再执行后面的命令。路径请使用正斜杠。上游有的逻辑用 `split("/")` 取任务名，反斜杠在 Windows 上会切不开。

PowerShell：

```powershell
$env:nnUNet_raw_data_base = "D:/data/nnUNet_raw"
$env:nnUNet_preprocessed = "D:/data/nnUNet_preprocessed"
$env:RESULTS_FOLDER = "D:/data/nnUNet_results"
```

bash：

```bash
export nnUNet_raw_data_base=/data/nnUNet_raw
export nnUNet_preprocessed=/data/nnUNet_preprocessed
export RESULTS_FOLDER=/data/nnUNet_results
```

程序会自己创建：

- `$nnUNet_raw_data_base/nnUNet_raw_data`：原始任务
- `$nnUNet_raw_data_base/nnUNet_cropped_data`：按非零区域裁剪后的中间结果
- `$nnUNet_preprocessed`：重采样和归一化后的训练数据、plans
- `$RESULTS_FOLDER/nnUNet`：权重、验证结果、`postprocessing.json`

## 3. 数据集构建

每个任务是一个以 `Task` 加三位编号开头的文件夹，放在 `nnUNet_raw_data` 下。图像和标签都是 NIfTI（`.nii.gz`）。

```text
D:/data/nnUNet_raw/nnUNet_raw_data/Task003_Liver/
  dataset.json
  imagesTr/
    liver_001_0000.nii.gz
    liver_002_0000.nii.gz
  labelsTr/
    liver_001.nii.gz
    liver_002.nii.gz
  imagesTs/                      # 只有测试图像时才需要
    liver_101_0000.nii.gz
```

命名规则：

- 训练图像：`病例名_模态编号.nii.gz`。单模态编号是 `0000`，第二模态是 `0001`，顺序必须和 `dataset.json` 里的 `modality` 一致。
- 训练标签：`病例名.nii.gz`，与图像病例名相同，不带模态编号。
- 标签是从 0 开始的连续整数，0 是背景。

`dataset.json` 至少要有这些字段。模态名写成 `CT` 或 `ct` 时，预处理才会走 CT 的百分位裁剪；写成 `MRI` 或其他名字则走 nonCT 的逐例 z-score。

```json
{
  "name": "Liver",
  "description": "liver and tumor",
  "tensorImageSize": "4D",
  "reference": "",
  "licence": "",
  "release": "0.0",
  "modality": { "0": "CT" },
  "labels": { "0": "background", "1": "liver", "2": "tumor" },
  "numTraining": 2,
  "numTest": 1,
  "training": [
    { "image": "./imagesTr/liver_001.nii.gz", "label": "./labelsTr/liver_001.nii.gz" },
    { "image": "./imagesTr/liver_002.nii.gz", "label": "./labelsTr/liver_002.nii.gz" }
  ],
  "test": ["./imagesTs/liver_101.nii.gz"]
}
```

`training[].image` 写的是不带 `_0000` 的路径，程序会按模态数量自行补后缀。

Medical Segmentation Decathlon 下载下来的是 4D NIfTI（模态在第一维）。先转成上面的 3D 文件：

```bash
uv run nnUNet_convert_decathlon_task -i D:/data/msd/Task03_Liver
```

转换结果会写到 `nnUNet_raw_data/Task003_Liver`（可用 `-output_task_id` 改编号）。

完整性检查、裁剪、规划、重采样和归一化：

```bash
uv run nnUNet_plan_and_preprocess -t 3 --verify_dataset_integrity
```

`-t` 后面是任务编号，不是文件夹全名。内存不够时减小 `-tf`（全分辨率）和 `-tl`（低分辨率）的进程数，例如 `-tf 2 -tl 2`。

这一步会生成 `nnUNetPlansv2.1_plans_3D.pkl` 等计划文件。计划里记录目标间距、patch 大小、归一化方案、是否用非零掩膜、轴转置，以及预处理器类名。3D 默认是 `GenericPreprocessor`，2D 默认是 `PreprocessorFor2D`。后面的训练和推理都读这份计划，不会各自再写一套归一化参数。

## 4. 训练

官方肝脏实验（5 折）在文档里是：

```bash
uv run nnUNet_train 3d_fullres nnUNetPlusPlusTrainerV2 Task003_Liver 0
uv run nnUNet_train 3d_fullres nnUNetPlusPlusTrainerV2 Task003_Liver 1
uv run nnUNet_train 3d_fullres nnUNetPlusPlusTrainerV2 Task003_Liver 2
uv run nnUNet_train 3d_fullres nnUNetPlusPlusTrainerV2 Task003_Liver 3
uv run nnUNet_train 3d_fullres nnUNetPlusPlusTrainerV2 Task003_Liver 4
```

`3d_fullres` 可换成 `2d`、`3d_lowres`、`3d_cascade_fullres`。只训一折时把最后的折号改成 `0`。任务参数也可以写数字 `3`。

训练器默认 1000 个 epoch，初始学习率 `1e-2`，SGD + 多项式学习率，混合精度默认开启。关掉混合精度加 `--fp32`。断点续训加 `-c`。

每一折训练结束时会在该折验证集上做滑窗推理、计算 Dice，并调用 `determine_postprocessing`，判断“只保留最大连通域”能否提高 Dice。单折的 `postprocessing.json` 写在 `fold_X` 里面。推理命令找的是折目录的上一级。五折都训完后执行：

```bash
uv run nnUNet_determine_postprocessing -t 3 -m 3d_fullres -tr nnUNetPlusPlusTrainerV2
```

它把五折原始预测收拢，重新决定一份实验级的 `postprocessing.json`。没做这一步时，`nnUNet_predict` 仍会输出分割，但会警告跳过连通域后处理。

## 5. 推理

输入文件夹的命名和训练图像相同：`病例名_0000.nii.gz`，多模态继续 `_0001`、`_0002`。

```bash
uv run nnUNet_predict -i D:/data/infer_in -o D:/data/infer_out -t Task003_Liver -m 3d_fullres -tr nnUNetPlusPlusTrainerV2
```

常用开关：

- `-f 0`：只用第 0 折。默认会用模型目录里实际存在的折，并对各折 softmax 取平均。
- `--disable_tta`：关闭镜像测试时增强。3D 大约快 8 倍。
- `--overwrite_existing`：覆盖已有输出。
- `-chk model_best`：改用其他 checkpoint，默认是 `model_final_checkpoint`。

输出是与原始图像几何一致的 `.nii.gz` 标签图。

## 6. 推理的预处理、后处理，以及和训练是否一致

推理预处理和训练预处理用的是同一类预处理器。3D 计划里写的是 `GenericPreprocessor`。推理时 `nnUNetTrainer.preprocess_patient` 按计划里的 `preprocessor_name`、`normalization_schemes`、`use_mask_for_norm`、`transpose_forward`、`intensity_properties` 和该 stage 的 `current_spacing` 调用 `preprocess_test_case`。训练前的 `nnUNet_plan_and_preprocess` 对每个病例调用的是同一个类的 `resample_and_normalize`。裁剪、转置、重采样、强度归一化这四步的参数来自同一份 plans，两边一致。

训练时额外打开的数据增强不会在推理时重放。这是刻意的：增强只存在于 `get_moreDA_augmentation` 的训练生成器里。

### 6.1 预处理（训练与推理相同）

对每个病例：

1. 用 SimpleITK 读入各模态，堆成 `(模态, x, y, z)`。
2. 非零体素并集做掩膜，再用 `scipy.ndimage.binary_fill_holes` 填洞，取外接框裁掉四周背景。裁剪框、原始尺寸、spacing 写进 properties，推理导出时要靠它贴回去。
3. 按 plans 的 `transpose_forward` 重排轴，让各向异性最强的轴落到固定位置。
4. 重采样到计划里的目标 spacing。图像用三次插值（order 3）；各向异性超过 3 倍时，低分辨率轴单独用最近邻（order 0）。标签在训练预处理里用 order 1，低分辨率轴 order 0。NaN 置 0。
5. 强度归一化，由 `dataset.json` 的模态名决定：
   - `CT`：用训练集前景的 0.5 和 99.5 百分位裁剪，再用训练集前景的均值和标准差做 z-score。
   - 其他（nonCT）：在本例有效区域内做 z-score。若裁剪让体积中位数降到原来的 3/4 以下，有效区域是非零掩膜，否则是整幅图。裁掉的背景位置写 0。

### 6.2 网络前向（只在推理）

`predict_preprocessed_data_return_seg_and_softmax` 在预测前把 `network.do_ds` 设为 `False`。此时 `Generic_UNetPlusPlus.forward` 只返回最深的嵌套输出 `x0_5`（全分辨率、所有跳跃连接都接上的那一支）。

默认推理是滑窗，步长 0.5。每个 patch 的权重是 `scipy.ndimage.filters.gaussian_filter` 生成的高斯图，重叠区域按权重平均。默认还做镜像测试时增强：沿镜像轴翻转再预测，概率平均。各折 checkpoint 的 softmax 再取平均。

### 6.3 几何还原（推理导出，训练验证用同一函数）

`save_segmentation_nifti_from_softmax` 把概率图变回原始图像网格，验证和推理走的是这个函数：

1. 用 `transpose_backward` 把轴序转回去。
2. 若当前形状和裁剪后的原始尺寸不同，把 softmax 重采样回去。默认阶数是 1（线性），各向异性轴阶数是 0。这是概率图的插值，和预处理时图像用的三次插值不是同一个阶数，但几何目标是裁剪后的原始网格。
3. `argmax` 得到标签。
4. 按 `crop_bbox` 贴回裁剪前的全尺寸画布，框外为 0。
5. 用 SimpleITK 写回原始 spacing、origin、direction。

所以分割和原始 NIfTI 在体素网格上对齐。预处理对图像做了裁剪和重采样，导出把这两步逆回去。

### 6.4 连通域后处理（可选，传统方法）

模型目录存在 `postprocessing.json` 时，`nnUNet_predict` 才做这一步。规则在验证集上选出来：对某些类别（或类别组合）用 `scipy.ndimage.label` 做连通域，保留最大一块，并删掉小于验证阶段记下的体积阈值的碎块。阈值存在才删，最大块始终保留。

这一步不在网络里，也不作用于训练输入。它只改推理（以及验证末尾）已经导出的标签图。没有 json 文件时，输出停在第 6.3 步的 argmax 结果。

### 6.5 和训练目标是否同一支输出

预处理一致，几何后处理是预处理的逆操作。网络监督的头和推理取出的头不一致，这是当前仓库里的实现：

- 训练时 `do_ds=True`，`forward` 返回一个元组。第 0 个是最深分支 `x0_5`，最后一个是上采样后的最浅分支 `x0_1`。
- `MultipleOutputLoss2` 只计算 `x[-1]` 的损失，也就是最浅分支。原本把其余分支加进损失的循环被注释掉了，`ds_loss_weights` 也被设成 `None`。
- 在线验证取的是 `output[0]`，推理在 `do_ds=False` 时返回的也是 `seg_outputs[-1]`，两者都是最深分支 `x0_5`。

因此：推理预处理与训练预处理一致；推理导出与验证导出一致；推理实际使用的分割头与训练损失监督的头不是同一支。在线验证 Dice 看的是推理会用的那一支，损失优化的是另一支。

## 7. 用到了哪些传统视觉方法

用了，都在神经网络外面，没有 OpenCV。

推理和训练预处理共用：

- 非零掩膜、`binary_fill_holes`、外接框裁剪
- 三次 / 线性 / 最近邻重采样（`skimage.transform.resize`，各向异性轴配合 `map_coordinates`）
- 百分位裁剪与 z-score

只在推理（和验证导出）使用：

- 滑窗高斯加权（`gaussian_filter`）
- 镜像翻转后再平均（测试时增强，不是经典滤波）
- 可选的连通域分析与小块删除（`scipy.ndimage.label`）

只在训练增强里使用，推理不会做：

- 旋转、缩放、弹性形变、镜像
- 高斯噪声、高斯模糊、亮度、对比度、gamma、低分辨率模拟
- `pyramid_augmentations.py` 里的形态学开闭、腐蚀、膨胀（随机作用在标签上）

部分 `dataset_conversion` 脚本（例如荧光显微镜任务）自己用了 `skimage.morphology` 的腐蚀、膨胀。那是把原始竞赛数据整理成 nnU-Net 目录的转换脚本，不是 `nnUNet_predict` 的后处理。
